# ERP 거래처 연동 — 전산팀 문의 사항

마일리지 관리 앱(`mileage-manager.vercel.app`)에 ERP 거래처 목록을 연동하려 합니다.
아래 항목을 확인해 주시면 개발을 시작할 수 있습니다.

## 하려는 것

ERP의 **거래처 마스터를 읽기 전용으로 조회**해서, 앱의 거래처 목록과 대조합니다.
- 신규 배정된 거래처를 자동으로 추가
- 앱에 손으로 적어 둔 거래처명에 **ERP 거래처코드**를 붙여 영구 식별자로 사용
- 상호명 변경·지점 이동을 따라감

쓰기는 하지 않습니다. ERP에 아무것도 입력하거나 수정하지 않습니다.

## 1. 가장 먼저 확인이 필요한 것 — 망 구분

**ERP API가 사내망에서만 접근 가능한가요?**

앱은 Vercel(외부 클라우드)에서 동작합니다. API가 사내망 전용이거나 IP 화이트리스트를
쓴다면 앱이 직접 호출할 수 없습니다. 이 경우 다음 중 하나가 필요합니다.

- 외부에서 호출 가능한 조회 전용 엔드포인트 (권장)
- 또는 사내 서버가 주기적으로 데이터를 내보내 주는 방식
- 또는 고정 IP 허용 등록 (Vercel은 기본적으로 고정 IP가 아니라 별도 설정 필요)

## 2. 엔드포인트

- 조회 URL과 HTTP 메서드
- 요청 파라미터 (담당자 사번·코드로 **내 거래처만** 필터할 수 있는지)
- 페이징 방식과 1회 최대 건수

## 3. 인증

- 인증 방식 (API Key / OAuth2 client credentials / 사번+비밀번호 등)
- 발급 절차와 키 유효기간·갱신 방법
- 키를 서버 환경변수에 보관합니다. 브라우저에는 절대 노출하지 않습니다.

## 4. 응답 형식

JSON 예시 한 건과 필드 설명이 필요합니다. 특히 아래 항목이 있는지 알려주세요.

| 항목 | 용도 |
|---|---|
| 거래처코드 | **영구 식별자.** 이게 핵심입니다 |
| 거래처명(상호) | 앱 표시명과 대조 |
| 사업자등록번호 | 동명이처 구분 |
| 지점·영업소 | 앱의 지점 필드와 대조 |
| 담당자(사번) | 내 거래처만 거르기 |
| 거래 상태 | 거래중지·해지 거래처 구분 |

## 5. 운영

- 호출 제한 (분당/일당 횟수)
- 점검 시간대
- 장애 시 문의 창구

## 참고 — 앱 쪽 처리 방식

- 키는 서버리스 함수의 환경변수에만 둡니다. 브라우저로 내려보내지 않습니다.
- 조회 주기는 하루 1회 정도를 예상합니다. 실시간 조회는 필요하지 않습니다.
- 기존 앱 데이터를 덮어쓰지 않고 **대조 결과를 사람이 확인한 뒤 반영**합니다.

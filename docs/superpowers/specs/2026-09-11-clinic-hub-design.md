# 거래처 원스톱 화면(거래처 허브) 설계

- 날짜: 2026-09-11
- 대상: `index.html` (단일 파일 웹앱, 5,306줄)
- 상태: 설계 확정, 구현 계획 대기

## 문제

거래처 한 곳을 처리하려면 화면을 네 번 옮겨야 한다.

1. `처방 입력`에서 거래선 고르고 처방 저장
2. `거래처 관리`로 이동해 잔액 확인
3. 거기서 `보고서` 모달 열어 이미지 복사
4. 판촉물을 보냈으면 `발송 관리`로 또 이동

거래처가 61곳인데 화면은 업무 종류로 나뉘어 있어, 정작 사람이 하는 단위인
"이 거래처를 정리한다"가 화면 어디에도 없다.

## 목표

거래처를 하나 고르면 그 거래처의 **잔액·적립 이력·차감 이력·처방 입력·판촉물 차감·
보고서**가 한 화면 안에서 끝난다. 화면 이동 없음.

## 비목표

- 기존 화면 삭제. 처방 이력·이력 조회·발송 현황은 여러 거래처를 가로로 훑는 용도라
  그대로 둔다.
- 딥링크(URL 해시). localStorage 기반이라 공유할 URL이 없다.
- 파일 분할. 필요하지만 개편과 섞으면 회귀 원인을 못 가린다. 개편 후 별건으로 한다.

## 화면

새 메뉴 `거래처` 하나 추가(`page-clinic-hub`), 앱 시작 화면으로 지정. 좌우 2단.

### 좌측 목록

- 검색창 + 정렬 (이름순 / 잔액순 / 오래된순)
- 한 줄: 거래처명 · 지점 · 잔액 · 마지막 처방 후 경과일
- 마지막 처방 종료일 후 30일 경과면 빨간 점, 잔액 음수면 빨간 숫자
- 선택된 줄 강조. 자체 스크롤(우측 패널과 독립)

### 우측 상세

헤더는 탭을 바꿔도 고정된다.

```
진정한하루치과 [파주지점]   적립률 15%                    [수정]
잔액 38,596    적립 38,596 (이전 0 포함)    차감 0
```

탭 4개.

| 탭 | 내용 |
|---|---|
| 요약 | 적립·차감을 시간순으로 합친 이력. 각 줄 [상세] |
| 처방 입력 | 기존 처방 입력 폼 그대로 (사진 인식 포함). 거래선 선택 줄만 숨김 |
| 차감 | 기존 판촉물 차감 폼 + 그 거래처 발송 이력 |
| 보고서 | 기존 보고서 미리보기·기간 수정·이미지 복사 |

## 구현 방식

### 제약: 폼이 전역 DOM id에 묶여 있다

세 폼 모두 거래처를 `<select>` 값에서 읽는다 (`#rx-clinic`, `#redeem-clinic`,
`#report-clinic`). 내부 필드도 전역 id다 (`rx-start`, `rx-end`, `redeem-date` …).
마크업을 복제하면 id가 겹쳐 양쪽 다 깨진다.

### 결정: 복제하지 않고 DOM 노드를 옮긴다

폼 인스턴스는 앱 전체에 하나만 둔다. 탭을 열 때 그 노드를 상세 패널로 옮기고,
거래처 화면을 떠날 때 원래 자리로 되돌린다.

- 옮길 단위에 id를 붙인다: `rx-workarea`, `redeem-workarea`, `report-workarea`
  (각각 `#page-prescriptions`·`#page-redeem`의 2단 그리드 div, 보고서 모달 본문)
- 헬퍼 두 개
  - `mountTab(tabName, clinicId)` — 원래 부모를 기억하고 패널로 이동, 거래처
    select에 `clinicId`를 넣고 그 줄을 숨김
  - `restoreTabs()` — 기억한 부모로 전부 되돌리고 숨긴 줄을 복구
- 저장 함수(`saveRx`, `saveRedeem`, `getReportData`)는 **수정하지 않는다**.
  여태처럼 select에서 거래처를 읽으면 맞는 값이 들어 있다.
- 인라인 `onclick` 속성은 노드를 옮겨도 그대로 동작한다.

이 방식의 대가는 명확하다. 거래처 화면에 들어가 있는 동안 기존 `처방 입력`·
`발송 관리` 화면은 폼이 비어 보인다. 되돌리기가 실패하면 그 화면이 망가진다.
그래서 `restoreTabs()`는 `navigate()`에서 거래처 화면을 벗어나는 모든 경로에
한 곳으로 모아 부른다.

### 새로 작성하는 함수

| 함수 | 역할 |
|---|---|
| `renderClinicHub()` | 좌우 2단 껍데기. 목록·패널 렌더 호출 |
| `renderClinicList(filter, sort)` | 좌측 목록 |
| `renderClinicPanel(clinicId)` | 헤더(잔액 요약) + 탭 바 + 탭 본문 |
| `selectHubClinic(clinicId)` | 선택 전환. 탭은 `요약`으로 초기화 |
| `buildClinicTimeline(clinicId)` | 적립·차감 합친 시간순 배열. **순수 함수** |
| `mountTab` / `restoreTabs` | 위 참조 |

저장 후에는 `renderClinicPanel(clinicId)`를 다시 불러 헤더 잔액과 요약 탭을 갱신한다.

### 기존 코드 변경

- `navigate()`에 `clinic-hub` 분기 추가, 벗어날 때 `restoreTabs()` 호출
- 시작 화면을 `dashboard` → `clinic-hub`로 변경
- 대시보드 `마일리지 정리 필요` 항목 클릭 → 거래처 화면 + 해당 거래처 선택
- `#page-prescriptions`·`#page-redeem`·보고서 모달에 `*-workarea` id 부여
- 잔액 계산(`getClinicBalance`)·보고서 계산(`getReportData`)은 건드리지 않는다

## 검증

- `scripts/validate-clinic-panel.mjs` — `buildClinicTimeline`의 정렬 순서와
  적립·차감 합계를 검증한다. `index.html`에서 함수 소스를 뽑아 실행하는 방식은
  `scripts/validate-ocr.mjs`와 같다
- 로컬 프리뷰(`python3 -m http.server 3456`)에서 실제 데이터로
  - 탭 4개를 왕복하고 각 폼이 정상 렌더되는지
  - 거래처를 바꿔도 폼이 새 거래처로 붙는지
  - 거래처 화면을 떠난 뒤 기존 `처방 입력`·`발송 관리`·보고서 모달이 멀쩡한지
    — **이 설계의 유일한 위험이라 매 단계 확인한다**
- 저장 후 헤더 잔액이 `적립(이전 포함) − 차감 = 잔액`으로 맞는지
